# singlet-website — standing instructions

singlet.bio: a catalog of re-processed public GEO single-cell RNA-seq studies. Everything runs on
Cloudflare: Pages (React/Vite SPA in `src/`), Pages Functions (API + MCP in `functions/`), D1
(`singlet-catalog`), R2 (`singlet-data` public files, `singlet-user-data` private uploads,
`singlet-hpc-dashboard`), Workers AI (`AI` binding). There is no Supabase or Lovable anywhere — do not add
either back.

## Working rules
- Branch + PR for every change. `main` auto-deploys to singlet.bio; PR branches get previews at
  `https://<branch-with-dashes>.singlet-4gc.pages.dev`. **Previews share the production D1 database.**
- CI (`.github/workflows/ci.yml`) runs `npm run build`, whose `prebuild` is vitest + strict
  `tsc -p tsconfig.functions.json` + `wrangler pages functions build`. It must be green before merge.
- Cloudflare reports the static deploy as green even when Functions fail to compile. After merging, confirm
  the change is live (hit an endpoint whose behaviour changed). `scripts/smoke.sh <base-url>` runs after every
  deploy to main (`smoke.yml`); run it against a preview before merging.
- A cluster bot ("Singlet Job-Orchestrator") still commits `public/data/hpc/*` to main every few hours until
  it switches to `POST /api/ingest/hpc` (README → "HPC dashboard uploads"). Rebase before pushing.
- `package.json` changes: the lockfile is regenerated by `lockfile.yml` on push (no local npm needed).

## Data model and invariants
- D1 schema files live in `schema/`. New tables go in a new numbered file with `CREATE … IF NOT EXISTS`, applied
  once to production (`wrangler d1 execute singlet-catalog --remote --file=schema/NNN_x.sql` or the
  Cloudflare D1 connector) **before** merging code that uses them. `010_accounts.sql` and `011_product.sql`
  are applied.
- "Downloadable" = `DOWNLOADABLE_SQL` in `functions/_shared/search-core.ts`: has a file, at least one usable
  sample (`sample_qc.usable`: matrix bytes > 400 and cells called > 0), no species/reference mismatch.
  Headline numbers are usable samples/cells in files (`/api/stats` samples_in_files, cells_in_files); label
  catalog metadata as such.
- The catalog crank (`/api/ingest/refresh-next`, `/api/ingest/index-next`) is idempotent and runs every 3 h
  from `catalog-crank.yml`. Both are public GETs that write production D1.
- D1 limits: never `json_each` over all of `bundle_index` (chunk by `gse_id`); ≤ 100 bound parameters per
  statement; watch the daily read budget.

## Auth and AI
- Sign-in: GitHub/Google OAuth (code + PKCE) in `functions/auth/*` and `functions/_shared/oauth.ts`; sessions
  are the `__Host-singlet_session` cookie hashed in D1 (`functions/_shared/session.ts`). Identity for every
  route comes from `resolveIdentity` / `requireUser` (`functions/_shared/identity.ts`); cookie auth only counts
  for unsafe methods from the same origin.
- Secrets (Pages → Settings → Variables and Secrets, Production + Preview): `GITHUB_CLIENT_SECRET`,
  `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, optional `ANTHROPIC_API_KEY`, `INGEST_TOKEN_SHA256`. Plain vars
  live in `wrangler.toml` (the source of truth for bindings/vars).
- AI search: `functions/_shared/interpret.ts` runs a deterministic vocabulary parse first (free); a model
  (`AI_MODEL`, Workers AI via AI Gateway, or Anthropic when `ANTHROPIC_API_KEY` is set) is called only for
  what the vocabulary can't place, charged to `ai_usage`. Organism is a hard filter and must come from explicit
  species words, never abstracts; tissue never comes from a disease word. Bump `INTERPRET_RULES_VERSION` when
  changing rules. The site, the MCP server and the Python/R clients all call `/api/nl-search`.

## Style
Match the surrounding code: comment density, naming, idioms. Keep copy short and factual — no superlatives.
Examples use GSE138867 (flagship) and GSE128639 (modalities). Python install line:
`pip install "singlet-bio @ git+https://github.com/Singlet-Bio/singlet"` (PyPI `singlet` is an unrelated
project).
