# singlet-website — standing instructions

singlet.bio: a catalog of re-processed public GEO single-cell RNA-seq studies. Everything runs on
Cloudflare: Pages (React/Vite SPA in `src/`), Pages Functions (API + MCP in `functions/`), D1
(`singlet-catalog`), R2 (`singlet-data` public files, `singlet-user-data` private uploads,
`singlet-hpc-dashboard`), Workers AI (`AI` binding). There is no Supabase or Lovable anywhere — do not add
either back.

## Working rules
- Branch + PR for every change. `main` auto-deploys to singlet.bio; PR branches get previews at
  `https://<branch-with-dashes>.singlet-4gc.pages.dev`. **Previews share the production D1 database.**
- CI (`.github/workflows/ci.yml`) runs `npm run check` (vitest + strict
  `tsc -p tsconfig.functions.json` + `wrangler pages functions build`) and then `npm run build` (vite only). It
  must be green before merge. Cloudflare's own build runs only `npm run build`; the tests need Node >= 22.13 for node:sqlite.
- Cloudflare reports the static deploy as green even when Functions fail to compile. After merging, confirm
  the change is live (hit an endpoint whose behaviour changed). `scripts/smoke.sh <base-url>` runs after every
  deploy to main (`smoke.yml`); run it against a preview before merging.
- A cluster bot ("Singlet Job-Orchestrator") still commits `public/data/hpc/*` to main every few hours until
  it switches to `POST /api/ingest/hpc` (README → "HPC dashboard uploads"). Rebase before pushing.
- `package.json` changes: the lockfile is regenerated by `lockfile.yml` on push (no local npm needed).

## Data model and invariants
- D1 schema files live in `schema/`. New tables go in a new numbered file with `CREATE … IF NOT EXISTS`, applied
  once to production (`wrangler d1 execute singlet-catalog --remote --file=schema/NNN_x.sql` or the
  Cloudflare D1 connector) **before** merging code that uses them. `010_accounts.sql` and `011_product.sql`
  are applied.
- "Downloadable" = `DOWNLOADABLE_SQL` in `functions/_shared/search-core.ts`: has a file, at least one sample that passed QC
  (`sample_qc.usable`: matrix bytes > 400 and cells called > 0, and `qc_tier = 0`), no species/reference mismatch.
- Sample QC (`functions/_shared/qc-rules.ts`, `docs/QC.md`): tier 1 = low QC (median genes < 30 or mapping < 20%), tier 2 =
  removed (mapping < 5% and genes < 10). `gse_meta.n_usable_*` count tier 0 only, so everything on `DOWNLOADABLE_SQL` leaves low-QC
  samples out by default; `include_low_qc=1` (API and MCP only) adds tier 1 back, tier 2 never counts. The website shows approved
  samples only: no low-QC, removed, failed or empty samples, toggles or counts. Show QC as gates crossed (`GateFunnel`), never as failures.
  Headline numbers count what a visitor can download: studies passing `DOWNLOADABLE_SQL` (`studies_with_files`), their usable samples and the cells called in them (`/api/stats` samples_in_files, cells_in_files). `files_published` is every file, `studies_withheld` the difference. Default searches total on the same basis (`totals.basis = "file"`), and `accounting` places every sample in exactly one bucket; label
  catalog metadata as such.
- Research Alpha exclusions (`schema/035`, `functions/_shared/alpha.ts`): samples in `alpha_exclusions` and studies in
  `alpha_withheld` are not part of singlet.bio. Every public query filters them (`sampleServedSql` / `studyServedSql`,
  `DOWNLOADABLE_SQL`, `servedEntries`); a withheld study answers 404. Load lists with `npm run alpha:sql` (from the data-guard
  policy JSON) and apply the files with wrangler; never hand-edit. Cells shown anywhere are cells called in files
  (`sample_qc.n_cells_called`, `gse_meta.n_usable_cells`), never `gsm.n_cells` / `gse.n_cells` (raw barcodes).
- The data format is `.s1` (Singlet-Bio/singlet docs/format-s1.md): one immutable object per sample under R2 `s1/`, served by
  `workers/data` on `data.singlet.bio/s1/*`. Catalog tables `s1_study` / `s1_sample` / `s1_migration` (schema/038, written by the
  campaign's catalog SQL or `POST /api/ingest/s1-study`). Nothing is named "store". `s1_flags.legacy_bundles = 'retired'` makes every
  verified study read as retired (no legacy URL anywhere; the data-guard Worker answers 410); `'served'` undoes it. Runbook: docs/S1-CUTOVER.md.
- Cell type, chromosomal sex and genetic ancestry from the .s1 labeller are public, searchable cell metadata (only raw genotype inputs are
  private): `sample_attr` pipeline facts and `study_label` (schema/039, `npm run s1:labels-sql`), search/facet filters
  `cell_type_label` / `sex_genetic` / `ancestry_genetic`, and the cells tables' label columns for `find_cells`.
- The catalog crank (`/api/ingest/refresh-next`, `/api/ingest/index-next`) is idempotent and runs every 3 h
  from `catalog-crank.yml`. Both are public GETs that write production D1.
- D1 limits: never `json_each` over all of `bundle_index` (chunk by `gse_id`); ≤ 100 bound parameters per
  statement; watch the daily read budget.

## D1 writes cost money: the owner approves every one, in Claude
D1 bills rows written, not statements: the row, every secondary index it touches and any full-text index rows (`gsm` is about 30 rows
per write). Workers Paid includes 50M rows a month, then $1.00 per million. The Sep 27 - Oct 26 2026 cycle wrote 419M rows into a
430 MB database and cost $370 of a $429.74 bill (`docs/CLOUDFLARE_COST_PLAN.md`). Everything else on the account was inside its free allowance.
- **Before any write to production D1** (INSERT / UPDATE / DELETE / DDL, `wrangler d1 execute|import|migrations apply`, the D1 HTTP API or MCP
  tool, `POST /api/ingest/*` or its cranks, the Anvil / Clipper publishers and campaign loops, `s1_campaign.py` catalog writes) you must stop
  and put a plan in front of the owner **in the Claude conversation**: what is written, how many rows per table, how many passes, the
  estimate from `npm run d1:estimate` (`-- file.sql`, or `-- --rows gsm=118000 --passes 3`) and the dollar figure. Then wait for a
  yes. A plan the owner has not answered is not approved; an earlier approval does not cover a different write, a bigger one or a repeat.
- A Claude Code hook (`.claude/settings.json` → `scripts/hooks/d1-write-approval.mjs`) also stops these calls and shows the estimate; approving
  the prompt is the owner's answer. Never work around it: no `--local` or dry-run flag to dodge the check, no splitting a write into
  small ones, no moving the write into a script the hook cannot see.
- **A loop is many writes.** Anything that runs repeatedly (cron, a self-resubmitting Slurm job, a per-study publisher) is estimated as
  rows per pass x passes, and must write only what changed: compare against D1 first (reads are nearly free: 25 billion included) and use
  `UPDATE ... WHERE col IS NOT ?` or `ON CONFLICT DO UPDATE ... WHERE <col> IS NOT excluded.<col>`. A publisher must not rewrite the whole
  catalog for one study.
- `/api/ingest/*` enforces a daily budget (`D1_DAILY_WRITE_ROWS`, default 1.5M estimated rows; 429 when spent). It is a Pages variable only
  the owner changes, after approving an estimate. Do not retry a 429 or look for another path to D1.
- The `gse_au` / `gsm_au` full-text triggers fire only when an indexed text column is in the SET clause (schema/040). Do not add columns
  to those triggers or write an unscoped `AFTER UPDATE` trigger on `gse` / `gsm`.
- Reads (`SELECT`, `--local`, `d1 time-travel info`, dashboards) are free to run. The monthly bill is on Cloudflare → Billing → Billable usage;
  alerts are set at $10 and every $50 up to $500.

## Auth and AI
- Sign-in: GitHub/Google OAuth (code + PKCE) in `functions/auth/*` and `functions/_shared/oauth.ts`; sessions
  are the `__Host-singlet_session` cookie hashed in D1 (`functions/_shared/session.ts`). Identity for every
  route comes from `resolveIdentity` / `requireUser` (`functions/_shared/identity.ts`); cookie auth only counts
  for unsafe methods from the same origin.
- Secrets (Pages → Settings → Variables and Secrets, Production + Preview): `GITHUB_CLIENT_SECRET`,
  `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, optional `ANTHROPIC_API_KEY`, `INGEST_TOKEN_SHA256`. Plain vars
  live in `wrangler.toml` (the source of truth for bindings/vars).
- AI search: `functions/_shared/interpret.ts` runs a deterministic vocabulary parse first (free); a model
  (`AI_MODEL`, Workers AI via AI Gateway, or Anthropic when `ANTHROPIC_API_KEY` is set) is called only for
  what the vocabulary can't place, charged to `ai_usage`. Organism is a hard filter and must come from explicit
  species words, never abstracts; tissue never comes from a disease word. Bump `INTERPRET_RULES_VERSION` when
  changing rules. The site, the MCP server and the Python/R clients all call `/api/nl-search`.
